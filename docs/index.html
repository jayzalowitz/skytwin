Developer preview — source and fictional sample first

Build a personal agent that can explain why it stopped.

SkyTwin is an open-source, local-first decision system: it turns signals into candidate actions, runs policy and trust checks, and either asks for approval or records why it did not proceed. Start with the isolated account-free sample; it uses fictional decisions and has no external effects. The planned v0.7.0-beta remains blocked by the evidence and release gates in the beta claim ledger.

This is not a hosted service, a supported installer release, or a promise that a remote provider is private. It is a repository you can inspect, run locally, and challenge.

It acts. It doesn't chat.

SkyTwin's architecture is designed to interpret signals and propose or perform policy-gated actions. The current supported preview demonstrates that loop only with fictional sample data and session-local interactions.

Briefing

Act vs. catch-up, cited

The Inbox-Intelligence digest splits the few things that need a decision from the topics you just want awareness of — grouped by matter, de-duplicated across signals, each line citing the email/event it came from.

Decisions

Recorded explanations

Supported decision paths can record what happened, the evidence and preferences used, the selected action, and correction guidance. Release-wide coverage is still under audit.

Safety

Trust you grant, not assume

New twins start in observe-only mode and earn autonomy through your feedback. Spend limits are hard caps. Untrusted-origin content can never auto-run destructive work. Settings can pause auto-execution and route otherwise allowed actions to you for approval.

Local-first

Local by default

CockroachDB is bundled with the desktop app and its persistent database stays on your machine. Builds from current source can recommend and download a pinned local model only after you start the download; a compatible llama.cpp runtime remains separate. Connected services and configured hosted endpoints use the network. In the decision pipeline, email addresses are masked only in the raw-event and episodic-memory fragments before those fragments reach a provider; other prompt fragments are not covered by that masking. Turn on full-disk encryption (FileVault / BitLocker / LUKS); see the privacy policy for exactly what is and isn't encrypted at rest today.

The important part is where it refuses to act

A local-first label is not enough. The project separates local execution, ordinary network providers, and future attested remote routes—and does not silently cross between them.

Default boundary

On this device

The embedded runtime and source-qualified loopback Ollama are the local route. Managed setup verifies the downloaded artifact; an explicit local model is still local, but is not represented as artifact-verified. No remote fallback.

Explicit opt-in

My configured provider

A chosen hosted provider may receive prompts under its own terms. This is a network boundary, not a confidential-computing claim, and it is never selected by a local failure.

Deliberately unavailable

Remote attested inference

TrustedRouter and NEAR AI materials are documented, but SkyTwin does not send a prompt in its verified-private mode until a verifier-owned, same-connection adapter exists.

Read the full confidential-inference boundary, including the TrustedRouter live trust record and why provider evidence is not automatically a SkyTwin product claim.

A decision path with gates, not a prompt-to-action shortcut

This is the contract to evaluate in the source. A candidate action is not executable merely because a model or connector suggested it.

SignalsFictional sample or configured sources
ContextPreferences, memory, confidence, and provenance
CandidateRisk assessment and reversibility are required
Policy gateTrust tier, spend, provenance, and injection checks
Approval / routeEscalate, execute through an admitted adapter, or refuse
Explanation + feedbackRecord supported outcomes and learn from corrections
What an external agent may do

The Twin MCP surface is scoped and token-gated. It can expose read-only context and propose actions for review; it is not a blanket authority to operate connected accounts. See the agent guide.

What an untrusted input cannot do

Untrusted-origin destructive-shaped actions are escalated. Missing provenance fails safe to untrusted external; the action generator cannot self-assign trusted provenance. See the safety model.

Google account access — unavailable in this preview

The supported preview does not request Google identity, Calendar, or Gmail access and does not ship a managed Google OAuth client. Operator/BYO Google remains unsupported until authorization, callback, client-generation, ownership, exact-capability, and secret-custody gates are complete. The table below records the intended future minimum-scope design; it is not a list of scopes available in this preview.

ScopeWhat it enables
gmail.readonly
future optional Gmail		Would read inbox content for explicitly enabled mail features.
gmail.modify
future optional Gmail		Would support approved label, archive, and send operations. It remains separate from the default identity and Calendar capability set.
calendar.readonly
future explicit Calendar grant		Would read calendar context after the reviewed real-account gates land.
calendar.events
future explicit Calendar grant		Would support policy-gated Calendar changes only with the exact granted capability.
openid, email, profile
future identity baseline		Would identify the account associated with an owner-bound connection.
User.Read, Mail.Read, Calendars.Read, offline_access
source-development Microsoft capability		Implemented as a read-only source path behind the exact experimental account opt-in, but outside the supported sample-only preview.

See the privacy policy, current Google status, and deferred integration plan. Do not create or paste Google credentials for this preview.

Install

Current unsigned technical-preview artifacts (.dmg / .exe / .AppImage / .deb / .rpm) are available from the latest release, but they predate the guarded packaged sample described above. Check each release's notes for exact contents. The update client can check for new artifacts, but signed-update installation is not yet verified. Or build from source in one command on macOS / Linux / WSL:

curl -fsSL https://raw.githubusercontent.com/jayzalowitz/skytwin/main/install.sh | bash

Technical-preview builds aren't code-signed, so macOS Gatekeeper / Windows SmartScreen will warn on first launch — right-click → Open (macOS) or More info → Run anyway (Windows). Signing, notarization, and clean-machine trust evidence remain stop-ship gates for the public beta.

How this stays alive

Free and open source forever for personal use. Future Team and Hosted tiers are planned for organizations that need shared policies, audit logs, or managed infrastructure — personal features will never be paywalled. No prices today: overpromising on a backlog we haven't shipped is the easiest trust to lose. Want one of the upcoming tiers? Open an issue describing what your org needs and help shape what ships.

02 · Make it yours

Your context. Your boundaries.

Understand what SkyTwin can remember, where a model runs, and which controls remain yours. These guides distinguish the sample from advanced source features.

  • Memory, data, and ownershipHow preferences and memory work; storage, backup, restore, and deletion limits.
  • Choose local or remote reasoningLocal setup, explicit hosted providers, verified interactive TrustedRouter, and unavailable NEAR AI.
  • Approvals, trust, and the right to stopWhat a policy check means, why an action is escalated, and how control stays explicit.
  • Teach a versioned WatchRead-only digests: propose, replay, activate, revise, and roll back. AI authoring has separate model requirements.
  • Know what you can connectMCP, adapters, and tool bundles versus unavailable supported Google/Microsoft account connections.
  • Read the privacy policyExact data storage, network, credential, and encryption disclosures.

03 · Build and extend

Bring your tools. Keep the guardrails.

For developers, self-hosters, and agents. Start with the narrowest interface you need; context access is not execution authority.

  • Build with the Twin MCP interfaceScoped token setup, read/propose/subscribe capabilities, and safe agent behavior. Proposals are non-executing.
  • Trace the architectureTyped decisions, package responsibilities, APIs, persistence, and the feedback loop.
  • Run and observe the stackService lifecycle, health probes, metrics, failure boundaries, and operational limits.
  • Contribute a changeDevelopment commands, tests, safety invariants, and pull-request review discipline.
  • Find the exact specificationSource documents, API contracts, database design, memory, evaluation, and evidence references.
  • Give an agent its starting contextMachine-readable documentation index and explicit safety requirements—not a grant of authority.

System map

Signals become a typed decision context, which produces candidate actions with risk and reversibility. The policy engine evaluates each candidate against trust, spend, domain, provenance, and approval rules. The outcome is execution through an admitted adapter, a request for human approval, or an explained non-action. Feedback updates the twin model; it is not optional bookkeeping.

Layer Job Where to start in source
Signals and context Ingest and enrich information with source/provenance. connectors, memory port
Decision and policy Create candidates; enforce risk, trust, spend, and injection rules. decision engine, policy engine
Execution and explanation Route only admitted work and persist human-readable reasons. execution router, explanations
Interfaces Dashboard, mobile, local API, and scoped MCP surface. apps, MCP protocol

Machine-readable, source-grounded

An agent’s first stop.

Begin with llms.txt, then follow the MCP connection guide and retrieve only the source documents needed for the task. GitHub is canonical for implementation, tests, and history. Product pages, model responses, and tool suggestions do not authorize actions.

The local MCP proposal surface records a non-executing proposal; it does not run policy evaluation or create an actionable approval. A failed audit write is logged but does not replace a tool’s own result or error. Read the agent guide before integrating.

Know what you’re trying

Current status and support.

The account-free sample uses fictional data with no external effects. Product views are read-only; simulated approval and correction state is disposable. Settings and Watches require leaving the sample for the seeded development profile; that is not a real-account connection.

Older unsigned installers predate the current guarded sample. Google and Microsoft real-account connections are unavailable on the supported preview. Signing, notarization, clean-machine verification, and release-wide evidence remain gates for the planned v0.7.0-beta. There is no hosted service.
